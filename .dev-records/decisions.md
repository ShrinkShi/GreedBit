# 技术决策记录

## 2026-11-03 - 高级委托改为内存单一真相源

### 背景
`advanced-orders.js` 用内存数组驱动撮合，`records.js` 的撤单却只改 localStorage。每笔成交后引擎把内存数组回写，已撤单复活；冻结金已退回，再撤一次即可无限退款。

### 决策
内存数组为唯一真相源；localStorage 只作为镜像。撤单统一走 `window.GreedBitAdvancedOrders.cancel()`。删除 `records.js` 的 localStorage 撤单实现与引擎的重复表格渲染。

### 原因
两套写入方无法保证一致性；任何一次回写都会覆盖另一方的删除。

### 代价
`records.js` 依赖引擎暴露的全局 API；引擎未加载时保留旧路径兜底。

### 替代方案
- 用 localStorage 作为唯一真相源：需要每次撮合前重新读取并解析，性能与一致性都更差。
- 引入事件总线：改动面更大，当前代码风格不匹配。

## 2026-11-03 - 平仓价格由 `closePosition` 内部按 symbol 决定

### 背景
调用方把全局 `price`（当前交易对现货价）当成交价传给 `closePosition`，跨品种减仓会捏造盈亏；高级委托又用现货价开仓、合约价平仓，形成基差套利。

### 决策
`closePosition` 内部按 `p.symbol` 取价：永续用 `contractPriceFor`，其余用 `markFor`；只有止盈/止损/强平这类「触发价」才允许调用方显式传入。

### 原因
价格必须由持仓的品种决定，而不是由界面当前看哪个品种决定。

### 代价
调用方需要区分「触发价」与「市价」，`events.js` 的减仓改为传 `null`。

### 替代方案
让每个调用方自己算价——无法阻止未来再次传错。

## 2026-11-03 - 已实现盈亏统一为净额，手续费只做聚合

### 背景
合约 `realized` 是毛额（费用另计），现货 `realized` 已扣费（费用又记一次），统计页 `netRealized()` 再统一减一次 `fees` → 现货双扣、合约「正确」，网格内部也不一致。

### 决策
所有 `realized` 一律为「扣除本笔相关手续费后的净值」；`accountStats.fees` 只做展示聚合，任何地方不再用它二次冲减收益。

### 原因
只有一份口径，才能让「钱包变化 = 已实现盈亏 + 未实现盈亏 + 资金费」成立。

### 代价
历史存档的累计值仍是旧口径，未做迁移。

### 替代方案
- 全部改回毛额、由统计层统一扣费：需要所有写入方都知道费率与分摊，改动面更大。
- 单独维护一套「净额累计」字段：又多一份状态。

## 2026-11-03 - 穿仓不再截断为 0

### 背景
平仓与资金费都用 `Math.max(0, usdt + delta)`，亏损超额时余额归零，但统计与账本记全额，账实不符。

### 决策
允许 USDT 余额为负；下单、划转、出金已有余额校验，会自动拦住后续操作。

### 原因
模拟器也应展示真实风险，截断会让穿仓不可见。

### 代价
资产页可能出现负数，需要产品接受。

### 替代方案
截断时写「穿仓豁免」流水冲减亏损——账能平，但风险仍被隐藏。

## 2026-11-03 - 全仓强平按账户权益求解，杠杆上限降到 100X

### 背景
旧 `liqPrice` 对每个全仓仓位都把 `margin + 全部可用余额` 当缓冲，同一份权益被重复抵押；200X 时 `ratio = 1/200 = MMR`，强平价恰好等于开仓价，下一次 tick 就以 0 盈亏强平。

### 决策
- 全仓用方程 `equity + PnL_i(P) − MMR × (notional_i(P) + 其他仓位名义) = 0` 求 P，权益只共享一次；
- `MAX_LEVERAGE` 设为 100，低于 `1/MMR = 200`，留出缓冲；
- 强平成交价用触发时的标记价，而不是理论强平价。

### 原因
同一份权益不能被 N 个仓位各自当缓冲；理论价成交会隐藏跳空风险。

### 代价
全仓强平价更近（更早强平），用户体感变化；预览价会随账户权益浮动。

### 替代方案
按维持保证金率逐级结算——更接近真实交易所，但实现复杂，暂不做。

## 2026-11-03 - 多标签页用修订号做单一写入

### 背景
每个标签页各持一份内存状态，`saveState` 整份覆盖同一个 key；两个标签页同时交易会互相覆盖、重复使用同一笔余额（双花），且没有任何冲突提示。

### 决策
- 每次保存递增 `greedbit_state_rev_<user>`，并与快照一起写入；
- 保存前比对修订号：落后就拒绝写入并安排一次重载 + 提示；
- 用户动作入口调用 `ensureStateFresh()`，落后时先重载再让用户重试；
- 监听 `storage` 事件，其他标签页写入后本页自动跟随；
- 去掉空闲 tick 与 60 秒定时器的无条件保存，避免「没改也算改」。

### 原因
完整状态无法自动合并；与其静默覆盖，不如让落后的标签页明确失败并刷新。

### 代价
同一时刻只有一个标签页能落盘；另一个标签页的操作会被拒绝一次（可立即重试）。

### 替代方案
- Web Locks 单写者 + 只读模式：UI 改动面太大；
- CRDT/操作日志合并：对纯前端存档来说过度设计。

## 2026-11-04 - 密码只存加盐哈希，管理员改成开发开关

### 背景
`greedbit_users` 里存明文密码，`admin/123456` 硬编码在前端，`isAdmin` 来自可写的会话 JSON——三件事叠加，任何人改一行 localStorage 就能进管理页。

### 决策
- 新增 `src/domain/hash.js`（同步 SHA-256），注册存 `{salt, hash, iter}`，登录校验哈希；
- 旧明文记录首次成功登录时自动迁移为哈希并删除 `password`；
- 删除硬编码管理员口令与 `isAdmin` 会话字段；
- 管理界面改为 URL `?admin=1` 的开发开关（写入 sessionStorage，仅当前标签页会话有效）。

### 原因
纯前端没有可信服务端，但至少不应把明文口令和万能口令写进仓库；权限也不应来自用户可编辑的字段。

### 代价
- 已存在的明文账号需要登录一次才能迁移；
- 管理界面不再有「密码」这一层，只有本地开关；忘记加参数就看不到入口。

### 替代方案
- WebCrypto PBKDF2：需要安全上下文且是异步，`file://`/局域网 http 下不可用；
- 保留管理员账号但改为哈希：仍需一个默认口令，等于没解决。

## 2026-11-04 - 覆盖链先文档化 + 门禁，而不是一次拆完

### 背景
运行时仍有 50 个被覆盖的全局函数、28 条多点链。一次性拆掉需要重排 21 个模块的初始化顺序，回归风险极高；但不记录又会让后来者改错文件。

### 决策
- 在 `RUNTIME_AUDIT.md` 中如实列出 Top 10 覆盖链与修改规则；
- 新增 `tools/runtime-ownership.mjs`：按真实加载顺序输出全量链，并在「赋值了但从未声明」时让 CI 失败；
- 明确「被取代的实现改为抛错 stub，不删除声明」。

### 原因
先用可执行校验锁住最危险的事故（删声明导致启动崩溃），把结构性重构留给后续独立迭代。

### 代价
覆盖链仍然是技术债；文档与脚本只能描述现状，不能自动消除分叉。

### 替代方案
- 立即把 21 个模块改成显式注册/依赖注入：收益最大，但一次改动面过大，缺少浏览器回归网；
- 只写文档不加门禁：文档会腐化，事故仍会发生。
