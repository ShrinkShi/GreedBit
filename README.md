# GreedBit

GreedBit 是一个面向网页与 Bilibili Toy 场景设计的虚拟货币交易模拟器。

项目参考主流数字资产交易终端的交互结构，但不连接真实交易所、不涉及真实资金，也不提供任何投资建议。目标是把行情、K 线、盘口、永续合约、杠杆、保证金、委托、持仓、风险控制与强制平仓做成一个有游戏性、同时尽量符合真实交易逻辑的模拟系统。

## 核心设计：K 线由行情过程形成

GreedBit 避免直接随机生成完整 OHLC 蜡烛。

```text
连续价格 Tick
      ↓
K 线聚合器
      ↓
Open  = 周期内第一个价格
High  = 周期内实际出现过的最高价格
Low   = 周期内实际出现过的最低价格
Close = 当前最新价格
```

因此当前蜡烛的实体和上下影线会随着行情逐步形成，周期结束后才封盘。

## 订单生命周期

v0.0.4 开始，限价合约委托拥有真实状态流转：

```text
提交限价单
   ↓
冻结保证金 + 预计手续费
   ↓
进入当前委托
   ├─ 用户撤单 → 解冻 → 历史委托：已撤销
   └─ 行情触价 → 转为持仓 → 历史委托：已成交
```

## 仓位风险链

```text
持仓
 ↓
实时标记价格
 ↓
未实现盈亏 / ROE / 强平价
 ↓
Tick 检查
 ├─ 触发止盈 → 平仓
 ├─ 触发止损 → 平仓
 ├─ 触及强平 → 强制平仓
 └─ 未触发 → 继续持有
```

逐仓主要使用仓位自身保证金承担风险；全仓还会使用账户可用余额作为风险缓冲。当前风险模型是游戏化近似，并不宣称复刻任一真实交易所的精确风险引擎。

## 资金费率

v0.0.4 加入模拟资金费率：

## 当前行情模型

行情仍使用纯前端本地模拟，主要由随机扰动、短期动量、阶段性趋势、偶发冲击和轻微均值回归共同驱动。

当前盘口仍是模拟深度，并非由完整订单簿真实撮合产生价格。这是目前最大的模型限制之一。

## 运行方式

项目没有构建步骤，也没有第三方运行依赖。

```bash
python -m http.server 8080
```

然后访问：

```text
http://localhost:8080
```

也可以直接打开 `index.html`。
